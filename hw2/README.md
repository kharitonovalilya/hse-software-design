# ПОС — Преподавательская оценка студентов

Домашнее задание 2 по курсу «Конструирование программного обеспечения».
Консольное приложение хранит студентов, рубрикатор и оценки в памяти одного запуска.

## Возможности

- Добавить, посмотреть, переименовать, перевести в другую группу или удалить студента.
- Собрать рубрикатор в черновике, посмотреть и исправить черновик, отменить его или опубликовать; затем изменить критерии.
- Выставить, посмотреть, исправить или отменить оценку. Для пары студент–критерий разрешена одна оценка.
- Рассчитать итог, посмотреть ведомость и выгрузить её в CSV.

В консоли доступны разделы «Студенты», «Рубрикатор», «Оценки», «Итоги и CSV».
ID выдаются автоматически и показываются при создании и просмотре. Удаление студента или критерия удаляет связанные оценки после подтверждения. Перезапись CSV тоже требует подтверждения.

## Запуск

Нужны Java 21 и Maven. Из папки `hw2`:

```bash
mvn clean verify
mvn dependency:build-classpath -Dmdep.outputFile=target/classpath.txt
java -cp "target/classes:$(cat target/classpath.txt)" pos.Main
```

Проверить только тесты: `mvn test`.

Сквозной сценарий: создать студента -> начать рубрикатор -> добавить критерии -> опубликовать -> выставить оценку -> исправить балл -> посмотреть итог -> экспортировать CSV. Например, при критериях «Работа» (максимум 10, вес 3) и «Проект» (максимум 20, вес 1), оценка 10 только за «Работу» даёт 75%.

```csv
student_id,full_name,group,result_percent
1,"Иванов, ""Иван""","БПИ-1",75.00
```

ID в примере зависит от порядка создания объектов.

## Предметная модель и язык

- **Студент** (`Student`) — тот, кого оценивают; у него есть ID, ФИО и группа.
- **Критерий** (`Criterion`) — часть рубрикатора с названием, положительным максимумом и положительным весом.
- **Оценка** (`Evaluation`) — балл студента по одному критерию и необязательный комментарий.
- **Итог** — вычисляемый процент по действующему рубрикатору и текущим оценкам, отдельной хранимой сущности нет.

`Student`, `Rubric`, `Criterion` и `Evaluation` - Entity: их различает ID, состояние может меняться.

`Score` - Value Object: неизменяемое значение балла без собственной идентичности.

`Rubric` — корень агрегата критериев: он обеспечивает уникальность названий (без учёта регистра), существование критерия и изменения его свойств.

`Student` и `Evaluation` — отдельные корни хранения. Связи оценок со студентом и критерием проверяются в сценариях приложения;

`Evaluation` с помощью `Rubric` проверяет диапазон при создании и исправлении.

`ResultCalculationService` повторно проверяет текущий максимум при расчёте, чтобы отвергать некорректные данные даже при обходе штатного сценария. Повторная оценка пары запрещена сервисом. Согласованность при удалении обеспечивают сервисы приложения и каскадное удаление оценок.

`ResultCalculationService` - Domain Service: расчёт затрагивает рубрикатор и набор оценок, проверяет принадлежность оценок студенту и отсутствие повторов. Непоставленный балл считается нулём.
- `weighted` вычисляет `100 × Σ((score / maxScore) × weight) / Σ(weight)`;
- `equal` вычисляет `100 × Σ(score / maxScore) / число критериев`.

После публикации можно удалить последний критерий: пустой рубрикатор допустим и результат равен 0%. Публикация изначально пустого черновика запрещена. Изменение весов или оценок сразу влияет на следующий расчёт.

## Архитектура и DI

Использованы Ports & Adapters:

```text
console -> PosFacade -> application services -> domain
                         ↓                     ↑
                  repository/export ports ← infrastructure adapters
```

`domain` содержит модель, правила, стратегии и порты репозиториев/генератора ID; он не зависит от Spring, консоли и CSV.

`application` содержит сценарии, `PosFacade`, неизменяемые модели чтения (`StudentView`, `RubricView`, `CriterionView`, `EvaluationView`, `ResultRow`) и порт экспорта. Консоль получает только снимки данных через фасад; изменить хранимую оценку или критерий можно только через сценарий приложения. Список ведомости упорядочен по ID студентов, оценки — по ID критериев.

`infrastructure` реализует InMemory-репозитории, последовательный генератор ID и CSV-экспорт. Консоль - входной адаптер, использующий только `PosFacade`; чтение и проверка ввода вынесены в `ConsoleInput`. `ApplicationConfig` создаёт application-сервисы и фасад, `DomainConfig` — Domain Service и две стратегии с именами `weighted` и `equal`. Порт `ResultExporter` получает строки ведомости и текстовое назначение; конкретный `Path` и файловые ошибки остаются внутри CSV-адаптера, который переводит сбой записи в стандартный.

Репозитории хранят данные только в памяти, поэтому после выхода всё исчезает. Черновик хранится в памяти сервиса и может быть отменён; рубрикатор один. CSV экспортирует итог, не сами оценки.

## Паттерны GoF

- **Builder (порождающий)** — `RubricBuilder` собирает критерии до публикации и не позволяет опубликовать пустой рубрикатор.
- **Facade (структурный)** — `PosFacade` даёт консоли одну точку для сценариев, чтобы UI не обращался к репозиториям.
- **Strategy (поведенческий)** — `ResultCalculationStrategy` позволяет выбирать расчёт с весами или равными долями без изменения модели оценок.

## Тестирование

Отдельные тесты проверяют границы баллов и критерия, уникальность названий, обе формулы с непоставленной оценкой, запрет повторной оценки, каскадное удаление, отмену и исправление черновика. Дополнительные проверки подтверждают, что фасад не отдаёт изменяемые доменные объекты, расчёт отвергает балл выше текущего максимума, а ведомость и оценки имеют стабильный порядок. Отдельный тест CSV проверяет экранирование и перезапись, тест консоли — сохранение контекста раздела после ошибки и отмену удаления.
